# M365 setup

This document describes the process to set up the lone worker application, covering the parts that require M365 admin permissions to perform.

- If you are setting up the application for the first time, you should follow *all* the steps in order.

- If you are *only* refreshing credentials (for example because they are due to expire), you should just obtain credentials - [step 5](#credentials).

- If you are *only* changing the users of the application, you should just perform [step 6](#configure-users) (and you need only perform steps for users that have been added, removed, or changed).

You will need a list of user email addresses and mobile phone numbers for lone workers who need to be tracked by the application, and email addresses of users who just need office access to it.

The steps are as follows.

1. Find the [M365 tenant identifier](#tenant).

2. Create a [shared mailbox](#shared-mailbox).

3. Set up an [app registration](#app-registration) (which here means an OAuth2 application, i.e. the security configuration, not the actual software).

4. [Restrict permissions](#restrict-permissions) for the app registration.

5. Obtain [credentials](#credentials) for the app registration.

6. [Configure the users](#configure-users) who are to use the lone worker application.

The outputs from this process are:

1. Tenant GUID

2. Email address of the loneworker application

3. ClientID for the app

4. ClientSecret and expiry date for the app.

Store these off securely, and inform the team setting up the application of their values.

## Tenant

[Find your organisation's tenant ID](https://learn.microsoft.com/en-us/sharepoint/find-your-office-365-tenant-id).

## Shared mailbox

You'll need a mailbox in the organisation that can be accessed by staff managing the application and appointments. For this, we use a [shared mailbox](https://learn.microsoft.com/en-us/microsoft-365/admin/email/about-shared-mailboxes). To create such an account, perform the following steps.

- As an administrator, log into the [Microsoft admin centre](https://admin.microsoft.com/Adminportal/Home#/homepage).

- Select the `Shared mailboxes` option, which is in the `Teams & Groups` section on the left hand bar.

- Click `Add a shared mailbox`, and assign it an email address and a name. Unless there is a deliberate choice to use a different email, use `loneworker@YOURDOMAIN`.

- After a little while (up to a minute or so), the new shared mailbox appears in the list of shared mailboxes.

Remember the shared mailbox email address.

## App registration

You now need to create and configure an *application registration*. This is the term that Microsoft Entra uses for a logical entity that has access rights, and which therefore can be granted permissions to the email account in question.

- Create the app registration

    - Go to the [Entra Admin Centre](https://entra.microsoft.com)

    - Select `Entra ID` on the list on the left of the page, and within that select `App Registrations`. (This used to be under `Applications`; if you are still seeing the old view, `App Registrations` may be there instead.)

    - Click the create (plus) button and fill out the fields in the resulting form

        - Pick the name `loneworker`. (This does not matter functionally, but you'll need to find it again, so it's best to pick the default.)

        - Who can access this API - select the option for just accounts in this organisation.

        - Do not enter a `Redirect URI` - leave it blank. (Nobody is going to use the OAuth2 Authorization Code Flow that this is used for.)

        - Save off the `client ID` (shown as `Application (client) ID` in the overview)

- You have now created an app registration, and you need to allow it to be used by external applications.

    - Open the `Authentication` tab for the app registration

    - Under `Settings` enable `Allow public flows`

- Now set up permissions under `API permissions` for the app registration in question. You need to do this entire process *for all of the permissions required*.

    - Click on `Add a permission`

    - Click the "Microsoft Graph" button in the list of services

    - Where there is a button to pick permissions type, pick `Application`

    - Pick the relevant permission. The permissions you need to have checked are as follows.

        - `Calendars.ReadWrite`

        - `Mail.Send`

        - `Contacts.Read`

        - `User.Read.All`

    - Accept the choice; the permissions should appear in the list of permissions for the application.

- Next to `Add a permission`, there is a button `Grant admin consent for <your tenant name>`. Click it.

## Restrict permissions

Unfortunately, the above grants the application rights to every mailbox in the enterprise, which is not such a good idea - everything will still work, but you have created credentials that have excessive permissions. The solution is to use PowerShell to set up permissions to restrict it to a single mailbox (or more accurately to a group consisting of a single mailbox, the shared mailbox you created above). Instructions for this process are the following.

- Go to the [Entra Admin Centre](https://entra.microsoft.com)

- Create a group.

    - Navigate to `Groups` on the left

    - Create a new group, of type `Mail-Enabled Security`, which we will assume is called `loneworker`.

    - Give it an email. This email should be one that stops people accidentally inviting it to meetings - so do not give it something that can easily be confused with the lone worker shared mailbox mail. `nomails@YOURDOMAIN` is a good example.

    - Description I picked was "Users whose accounts the loneworker app can access"

    - Find and store the object ID GUID for the security group. This will be used as the `PolicyScopeGroupId` below.

- Add the shared mailbox to the group

    - Find the group

    - Click on `Members` and add the relevant users (i.e. the shared mailbox which above we called `loneworker@mycharity.org`).

- Use PowerShell (on Windows or Linux) to run the commands below.

    - Install the relevant module.

        ~~~powershell
        Install-Module -Name ExchangeOnlineManagement -Scope CurrentUser
        ~~~

    - Connect to Exchange Online as the admin user of the account.

        ~~~powershell
        Connect-ExchangeOnline -UserPrincipalName <YOUR_EMAIL>
        ~~~

    - Create a policy; note that you must substitute your application ID (the client ID you saved off above) into the string.

        ~~~powershell
        New-ApplicationAccessPolicy -AppId <YOUR_APP_ID> `
        -PolicyScopeGroupId <THAT_GUID_YOU_SAVED> `
        -AccessRight RestrictAccess `
        -Description "Restrict app access to allowed mailboxes only"
        ~~~

    - Test the policy for a specified mailbox. This should work for the shared mailbox, and fail for any other mailbox in the tenant.

        ~~~powershell
        Test-ApplicationAccessPolicy -Identity <TEST_USER_EMAIL> -AppId <YOUR_APP_ID>
        ~~~

## Credentials

You must now create or update credentials that allow the lone worker application in AWS to sign into it, as follows.

- Go to the [Entra Admin Centre](https://entra.microsoft.com).

- Select `App registrations` on the left panel.

- Click on the `loneworker` application to show options for that app registration.

- Click on `Certificates & secrets` to display the list of secrets.

- Click `New client secret` to create a new secret.

    - The name is not meaningful, but as you are likely to have multiple such objects owing to rotation of secrets, a name such as "loneworker YYYY-MM" is clear.

    - The expiry time should be as long as possible, which normally means one year.

- Save the secret value and expiry date securely. You will never see this value again, so if you lose it, you will have to create a new secret. *Note that you must save the secret value, not the secret ID; the GUI can be confusing*.

- **Do not delete any old secrets unless they have expired; they may still be in use. Once expired, they may safely be deleted for simplicity**

## Configure users

You must configure each user who is to use the loneworker application.

1. [Grant them rights to the shared mailbox](#grant-shared-mailbox-rights)

2. [Configure mobile phone numbers](#configure-mobile-phone-numbers)

### Grant shared mailbox rights

All users who are to be tracked or who are office staff who manage the system must be members of the shared mailbox.

- As an administrator, log into the [Microsoft admin centre](https://admin.microsoft.com/Adminportal/Home#/homepage).

- Select the `Shared mailboxes` option, which is in the `Teams & Groups` section on the left hand bar.

- Click on the shared mailbox name (normally `Lone Worker Shared Mailbox`).

- Under `Member`, click on `Edit`

- Add all of the users to the list, whether office staff or lone workers (all of whom should be able to view and edit the calendar).

### Configure mobile phone numbers

Every person who is to be tracked by the lone worker application must have a mobile phone number configured.

- Go to the [users tab](https://admin.microsoft.com/Adminportal/Home?#/users) in the Office 365 admin portal.

- Select the user in question.

- Click `Manage contact information`

- Set up the `mobilePhone` field (called `Mobile phone` in some places). If this is a UK phone number, then you can use `07123123456` or `+447123123456` format; for a foreign number you must use the number format with `+`.
